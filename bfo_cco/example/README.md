# Example: the same data with and without the bfo_cco archetype

A small fleet-maintenance dataset is loaded into two databases: one created without the
archetype and one created with it. Seven queries run unchanged against both. The only
difference between the databases is the archetype plus a 24-axiom alignment of the fleet
ontology to CCO (`fleet_cco_alignment.ttl`).

## Files

| File | What it is |
|---|---|
| `fleet_ontology.ttl` | The domain ontology: 17 classes (fighter and transport aircraft, tanks, trucks, satellites, engines and their modules, targeting pods, cameras, bases, hangars, maintenance events, …) and 12 properties. It has no BFO/CCO terms. |
| `fleet_cco_alignment.ttl` | The alignment: 17 `rdfs:subClassOf` axioms to CCO classes and 7 `rdfs:subPropertyOf` axioms to BFO relations. It is loaded only into the archetype database, and it is the template for aligning your own ontology. |
| `fleet_data.ttl` | Generated by `gen_fleet_data.py`: 14 aircraft, 26 engines (each with a fan module, a core module and a fan blade set), 11 ground vehicles, 2 satellites, 6 targeting pods with infrared cameras, 3 bases, 5 facilities and 12 maintenance events. |
| `incoming_batch.ttl` | An unmerged batch with one mapping error: AF-1011 is typed as both an aircraft and a maintenance event. It is loaded into its own graph. |
| `queries/*.rq` | The seven comparison queries. Each header gives the question and the expected result for each database. |
| `load_example.sh` | Creates and loads both databases over the HTTP API (curl only). |
| `compare.py` | Runs every query against both databases and prints the results side by side (standard library only). |

## Run it

1. Install the archetype on the server (see the archetype README, "Installation").
2. Create the example databases, `bfo_cco_example_plain` and `bfo_cco_example`:

   ```
   $ ./load_example.sh http://localhost:5820 admin:admin
   ```

   Add `VOICEBOX=1` to also enable Voicebox and semantic search; this is needed for
   `../tests/voicebox`. Add `RECREATE=1` to replace existing databases with the same names.

3. Compare:

   ```
   $ python3 compare.py --endpoint http://localhost:5820
   ```

## Expected results

With reasoning on, on Stardog 12.1.1:

| Query | Without the archetype | With bfo_cco |
|---|---|---|
| 01 Vehicles by CCO type | no rows | Aircraft 14, Ground Vehicle 11, Spacecraft 2 |
| 02 Sensors (nothing is typed Sensor in the data) | no rows | 8: six infrared cameras and two satellites, classified through their sensor capability |
| 03 Components of AF-1001 at any depth | no rows | 6: engine, fan module, core module, fan blade set, targeting pod, infrared camera |
| 04 Everything at Kirtland AFB, including inside its hangars | no rows | 9: two hangars and seven aircraft |
| 05 Physical inventory | no rows | 151 material entities (27 vehicles, 26 engines, 8 facilities, 6 imaging instruments, …) |
| 06 Anything in the incoming batch that is both a thing and an event | no rows | AF-1011 |
| 07 Control: number of fighter aircraft (domain-only) | 10 | 10 |

The SHACL shapes report the same AF-1011 error: `POST /bfo_cco_example/icv/report`, or
`stardog icv report bfo_cco_example`.

## What to take from it

- The alignment file is the only domain-specific work. Queries 01–06 depend on it: without
  it, the archetype database would also return no rows.
- Query 07, and a reasoning-on count of every fleet class (identical with and without the
  archetype), show that adding BFO/CCO does not change answers to existing domain queries.
- Every query binds its `rdf:type` objects to constant IRIs, which keeps reasoning queries
  fast (see "Known issues" in the archetype README).

## Natural-language (Voicebox) comparison

`../tests/voicebox` asks 13 questions of Voicebox against both databases. Seven questions
depend on BFO/CCO; six are domain-only controls.

| | With the archetype | Without |
|---|---|---|
| 3 runs per question | 38 of 38 answered correctly, plus one intermittent Voicebox error | 31 of 39 |
| Domain-only questions | 18 of 18 | 18 of 18 |

The model was `claude-haiku-4-5`. Voicebox found CCO terms such as Sensor, material
entity and *has continuant part* through the semantic index, and used them in its
generated SPARQL.
